# Domain Model
## Overview

The urban intelligence platform represents a smart city environment composed of connected systems, sensors, infraestructure  assets, public transport services, and operational events.
The platform collects simulated data, stores historical information, detect anomalies, and support technical and operational analysis.

## Main Domains

### 1. Traffic
The traffic light  domain represents systems responsible for monitoring and controlling urban road traffic

Main entities: 
- traffic light
- intersection
- road
- traffic camera
- vehicle counter

### 2.Public Transport

The public transport domain represents the operation of buses, trams, metro services, routes, and stations.

Main entities: 
- Vehicle
- Bus
- Metro
- Station
- Route
- Trip

### 3. Utilities
The  utilities domain represents essential urban services and their monitoring equipment.

Main entities: 
- Street light
- Energy Meter
- Water Meter
- Water Pressure Sensor
- Electricity Distribution Point

  ### 4. Environment
  The environment domain represents sensors and stations used to monitor environmental conditions.

  Main entities:
  - Weather Station
  - Air Quality Sensor
  - Noise Sensor
  - Temperature Sensor
  - Rain Sensor
 
    ### 5. Infraestructure
The Infraestructure domain represents physical city assets that require continuous monitoring and maintenance

Main entities: 

- Bridge
- Tunnel
- Public Building
- Structural Sensor
- Maintenance Record

### 6. Emergency Services

The emergency services domain represents emergency resources, stations, and incidents.

Main entities:

- Ambulance

- Fire Vehicle

- Police Vehicle

- Fire Station

- Police Station

- Emergency Incident

## Shared Entities

### Sensor

Represents a device that collects measurements from the city environment.

Main attributes:

- sensor_id

- sensor_type

- domain

- asset_id

- location

- status

- installation_date

- last_update

### Measurement

Represents a value collected by a sensor.

Main attributes:

- measurement_id

- sensor_id

- metric_name

- metric_value

- unit

- timestamp

### Event

Represents an operational occurrence generated by a system or city asset.

Main attributes:

- event_id

- source_id

- event_type

- severity

- description

- timestamp

- status

### Anomaly

Represents an unusual behavior detected in measurements or events.

Main attributes:

- anomaly_id

- source_id

- measurement_id

- anomaly_type

- anomaly_score

- reason

- detection_method

- detected_at

- status

### Asset

Represents a physical or logical city component.

Main attributes:

- asset_id

- asset_type

- domain

- name

- location

- operational_status

- installation_date

### Location

Represents the geographical position of an asset, sensor, or event.

Main attributes:

- location_id

- district

- street

- latitude

- longitude


## Data Integration and Normalization

The Urban Intelligence Platform receives data from multiple vendors and external systems.

Since each vendor may use different payload structures, field names, units, identifiers, and schema versions, the platform normalizes all incoming data into a canonical data model before storage and analysis.

### Vendor

Represents a manufacturer or external data provider.

Main attributes:

- vendor_id
- vendor_name
- vendor_type
- supported_protocol
- schema_version
- status

### Raw Payload

Represents the original message received from an external system.

Main attributes:

- raw_payload_id
- vendor_id
- device_id
- payload_format
- payload_content
- schema_version
- received_at
- processing_status

### Vendor Adapter
Responsible for converting vendor-specific payloads into the platform's canonical format.

Main attributes:

- adapter_id
- vendor_id
- source_schema_version
- target_schema_version
- adapter_version
- status

### Field Mapping

Defines how vendor-specific fields are mapped to the canonical model.

Main attributes:

- mapping_id
- vendor_id
- source_field
- target_field
- transformation_rule
- source_unit
- target_unit
- required
- default_value

### Normalized Record

Represents a validated and normalized record ready for storage.

Main attributes:

- normalized_record_id
- raw_payload_id
- sensor_id
- metric_name
- metric_value
- unit
- timestamp
- normalization_status
- adapter_version

### Integration Anomalies

Examples of anomalies detected during data ingestion:

- Unknown vendor
- Unsupported schema version
- Missing required field
- Invalid timestamp
- Unknown status code
- Invalid unit conversion
- Payload structure mismatch
- Duplicate message
